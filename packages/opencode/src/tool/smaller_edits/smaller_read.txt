Read a file or directory from the local filesystem. If the path does not exist, an error is returned.

Usage:
- The filePath parameter should be an absolute path.
- This smaller read tool is intentionally chunked. By default it returns up to 200 lines and caps reads at 400 lines even if you request more.
- The offset parameter is the line number to start from (1-indexed).
- To read later sections, call this tool again with a larger offset instead of asking for the whole file.
- For text files, each returned line uses the active line-anchor rendering format. Copy the full rendered anchor prefix exactly when you later call the smaller edit tool.
- The rendered anchor prefix is not part of the file content. When you prepare replacement text, copy only the content portion.
- Successful text reads refresh the in-process sparse remembered state only for the emitted window. Unread gaps remain unknown and may need another read before an edit can target them.
- Use the grep tool to find specific content in large files or files with long lines.
- If you are unsure of the correct file path, use the glob tool to look up filenames by glob pattern.
- For directories, entries are returned one per line with a trailing `/` for subdirectories.
- Output is also byte-capped to keep each observation compact. If a chunk is truncated, continue with the suggested offset.
- Any line longer than 2000 characters is truncated.
- Call this tool in parallel when you know there are multiple files you want to read.
- Avoid tiny repeated slices (30 line chunks). If you need more context, read a larger window.
- This tool can read image files and PDFs and return them as file attachments.
